## 1. 量化基础：35 分钟

### 1.1 量化与反量化

```text
量化：
q = clamp(round(x / s) + z, q_min, q_max)

反量化：
x_hat = s × (q - z)
```

| 符号 | 含义 |
| --- | --- |
| x | 原始浮点数 |
| q | 量化后的整数 |
| s | scale，量化步长，通常为正数 |
| z | zero point，浮点数 0 对应的整数值 |
| round | 舍入到整数；具体实现要明确舍入规则，例如最近偶数舍入 |
| clamp | 将结果限制在合法整数范围 |
| x_hat | 反量化后的近似值 |

例子：

```text
x = 1.23，s = 0.1，z = 0，假设没有超出整数范围

q = round(1.23 / 0.1) = 12
x_hat = 0.1 × 12 = 1.2
误差 = x_hat - x = -0.03
```

反量化不是恢复原始数据，而是恢复对应量化格点上的近似值。

常见的非对称 MinMax 参数选择可写成：

```text
s ≈ (x_max - x_min) / (q_max - q_min)
z ≈ clamp(round(q_min - x_min / s), q_min, q_max)
```

实际实现还要处理范围包含零、全零输入、scale 下限、舍入和边界约定。对称量化的一种常见 INT8 约定是使用 [-127,127]，取 s=max(abs(x))/127、z=0；不要把这一约定当成所有库的唯一实现。

### 1.2 粒度：per-tensor / per-channel / per-group

| 粒度 | 参数共享范围 | 权衡 |
| --- | --- | --- |
| per-tensor | 整个张量共享一组 scale/zero | 元数据少、实现简单，但容易受不同通道范围差异影响 |
| per-channel | 每个指定通道一组参数 | 更能适应通道间分布差异；必须说清楚沿哪个轴 |
| per-group | 每组若干元素一组参数 | 低比特权重量化常见；粒度更细，元数据与处理成本增加 |

统一采用数学记号：

```text
X：[M,K]
W：[K,N]
Y = XW：[M,N]
```

注意 PyTorch Linear 的实际 weight 通常存成 [N,K]，计算相当于 X × weight.T。讨论 group 的方向时，先明确使用数学布局还是存储布局。

例如沿 K 维分组，每个输出通道分别保存参数，group size=128：

```text
W[k,n] 对应的 group = k // 128
W_hat[k,n] = scale[group,n] × (q[k,n] - zero[group,n])
```

group size 从 128 改成 32，通常能更贴合局部分布，但参数数量增多；精度和速度改善均需实测，不能保证单调。

### 1.3 误差、离群值与校准

两类主要误差：

- 舍入误差：范围内的浮点值被映射到离散格点。
- 截断误差：超过选定范围的值被压到边界。

极端值可能把 scale 撑大，让大部分普通值的量化步长过粗。裁剪范围是在截断误差和舍入误差之间取舍。

校准使用有代表性的数据观察激活或优化量化参数，不等于重新训练整个模型。先理解以下方法的目的即可：

- MinMax：覆盖观测到的数值范围。
- 百分位裁剪：允许少量极端值被截断。
- MSE 搜索：寻找重建误差较小的量化范围。

不同方法对校准数据的需求不同；不能说所有 PTQ 都需要同一种校准流程。

### 1.4 PTQ、QAT、静态与动态

| 概念 | 应掌握的解释 |
| --- | --- |
| PTQ | 训练完成后量化，可能包含校准、缩放搜索或误差补偿 |
| QAT | 训练中模拟量化误差，使参数适应；常见 fake quant、STE |
| fake quant | 前向模拟量化和反量化误差，通常仍以浮点张量参与训练 |
| STE | 对舍入等不可导操作采用近似梯度；不必在此阶段深挖全部变体 |
| 静态量化 | 相关量化参数提前确定，例如用校准集确定激活 scale |
| 动态量化 | 运行时依据当前数据确定相关量化参数，需要考虑统计和量化成本 |

### 1.5 W4A16、W8A8、FP8

```text
W4A16：权重 4 位，激活 16 位
W8A8：权重 8 位，激活 8 位
```

这些简称不能单独决定累加类型、输出类型或底层指令。

重点记住：

- W4A16 可以是 INT4 存储权重，运行时反量化后进行浮点乘加。
- W8A8 还需要明确是 INT8 还是 FP8 等具体格式。
- FP8 是浮点格式，常见 E4M3、E5M2 的动态范围与精度不同，不能直接套用 INT8 的均匀整数格点理解。
- 权重量化和 KV cache 量化是不同配置，不能从模型名带 FP8 推断 KV 也是 FP8。

参考：[TensorRT 量化格式、粒度和公式](https://docs.nvidia.com/deeplearning/tensorrt/latest/inference-library/quantized-types-schemes.html)。该页面中的支持范围是 TensorRT 的产品约束，不要外推为所有框架或硬件的限制。

## 2. 三种代表算法：45 分钟

### 2.1 GPTQ：优先掌握

普通逐元素舍入关注单个权重如何落到量化格点。GPTQ 利用校准输入和近似二阶信息，在量化部分权重后调整尚未量化的权重，补偿层输出误差。

核心目标：

```text
X：校准输入
W：原始权重
W_hat：量化后重建的权重

尽量减小：||XW - XW_hat||_F²
```

它关注层输出误差，不只是 ||W-W_hat|| 的大小。同样大小的权重误差，落在不同输入通道上，对输出的影响可能不同。

学习顺序：

1. 为什么需要校准输入 X。
2. 为什么独立舍入并非最佳。
3. 量化一部分、补偿剩余部分的基本思路。
4. X.T × X 如何提供输入通道相关性和二阶误差信息；暂不要求背完整推导。
5. act-order、group size 的含义；具体实现可以包含排序与重排元数据。

关键区分：GPTQ 是离线权重量化方法；推理 kernel 读取它生成的量化权重，并不会每个 token 都重新执行 GPTQ 的误差补偿优化。

资料：[GPTQ 原论文](https://arxiv.org/abs/2210.17323)、[官方核心实现 gptq.py](https://github.com/IST-DASLab/gptq/blob/main/gptq.py)。先看思想，再选择性阅读实现。

### 2.2 AWQ：激活感知的权重量化

核心：权重对输出的重要性不能只看权重数值，还要参考激活分布。AWQ 用校准激活统计寻找重要通道，通过等价缩放等处理降低低比特权重量化误差。典型配置是 W4A16：权重使用 INT4 存储，激活保持 FP16/BF16。

#### 2.2.1 为什么 AWQ 和 SmoothQuant 看起来很像：共同的等价缩放

两者都可以使用下面的变换。沿用本文的数学布局，不是 PyTorch 权重的存储布局：

```text
X：[M,K]，输入激活；M 可以理解为本次参与计算的 token 数
W：[K,N]，权重
Y = X @ W

为每个输入通道 k 选择一个正的缩放系数 s[k]：

X_new[:,k] = X[:,k] / s[k]
W_new[k,:] = W[k,:] * s[k]

X_new @ W_new = X @ W
```

参与乘法的两侧一除一乘，互相抵消。上述等价指未量化时的数学关系，实际浮点计算仍可能有舍入差异；量化后更不保证结果完全相同。

缩放沿 Linear 的输入通道 K 进行：

- X 的第 k 列，即不同 token 的同一特征，共享 s[k]。
- W 的第 k 行，即该输入特征通往不同输出通道的权重，共享 s[k]。
- PyTorch 的 `Linear.weight` 存储为 [N,K]，因此在那种布局下是缩放权重的第 k 列。
- 每个相关 Linear 或共享输入的一组投影有各自的缩放配置，不是整个模型所有层共用一条向量。

这里有两种不同的 scale，不能混淆：

| 参数 | 作用 | 示例形状 |
| --- | --- | --- |
| 通道调整系数 s[k] | 在量化前重新分配激活和权重的数值幅度 | [K] |
| 量化步长 scale[g,n] | 将浮点权重映射到整数格点，再用于反量化 | 沿 K 分组时为 [ceil(K/group_size),N] |

所以“按输入通道缩放”和“按 group 量化”可以同时存在。group size=128，不代表每 128 个输入通道只能有一个 s；它表示对应量化组共享量化步长/零点。

#### 2.2.2 为什么看激活，却主要量化权重

先看一个乘积对输出的贡献：

```text
y = x * w
w_hat = w + δw

权重量化引入的输出误差：δy = x * δw

如果 δw 都是 0.01：
x = 1   → 该项输出误差 0.01
x = 100 → 该项输出误差 1
```

因此，权重本身不一定很大，但它对应的激活如果经常很大，其量化误差就可能对输出产生更大影响。完整输出还包含不同通道误差的求和，不能仅凭一个元素断言整个模型的误差。

AWQ 根据校准激活统计判断重要通道，再通过缩放改善其量化精度。Activation-aware 指“量化权重时参考激活”，不意味着主要量化激活。

#### 2.2.3 放大权重为什么能降低误差

下面是解释机制的简化例子，不是模型实测。假设同一量化组的步长在缩放前后都保持为 0.1，且没有截断：

```text
原始：x = 10，w = 0.12
真实乘积 = 1.2

直接量化：
w_hat = 0.1
结果 = 10 * 0.1 = 1.0
误差 = -0.2

将这个通道的权重放大 4 倍，同时缩小激活：
x_new = 10 / 4 = 2.5
w_new = 0.12 * 4 = 0.48

量化后：w_new_hat = 0.5
结果 = 2.5 * 0.5 = 1.25
误差 = +0.05
```

在原权重的尺度上看，放大后再除回来，相当于获得更细的有效刻度。若新量化步长是 Δ_new，原尺度上的有效步长就是 Δ_new/s。

但这不是无限放大的理由：

- 如果放大后的权重抬高了整组范围，Δ_new 也会增大，可能损害同组其他权重。
- 如果把整个量化组全部同比例放大，步长也同比例放大，通常不会凭空提高精度。
- 因而关键是不同通道的相对缩放，以及它对共享量化步长的影响。

AWQ 会搜索缩放强度，比较量化后的输出误差。论文给出的一种搜索参数化是：

```text
a[k] = 校准输入中，第 k 个通道的平均绝对激活值
s[k] = a[k]^α

尝试不同 α：
    调整权重 → 模拟量化/反量化 → 计算校准输入的输出
    → 与未量化输出比较 → 选择误差较小的缩放方案
```

这是离线搜索，不是每生成一个 token 都重新做一遍。搜索候选缩放并评价误差，也不等于反向传播训练整个模型。具体实现还可能包含裁剪等处理，不能把这个简式当成所有 AWQ 工具的完整流程。

不要误说：

- Activation-aware 不等于“主要量化激活”。典型 AWQ 是 weight-only。
- 保护重要权重不等于必须把那部分权重单独保留为 FP16；其关键设计包括通过缩放避免不规则混合精度带来的实现成本。

资料：[AWQ 原论文第 3.2 节](https://arxiv.org/html/2306.00978v5)、[AWQ 项目说明](https://hanlab.mit.edu/projects/awq)、[官方缩放搜索实现](https://github.com/mit-han-lab/llm-awq/blob/main/awq/quantize/auto_scale.py)。

### 2.3 SmoothQuant：把激活的量化难度转移给权重

典型目标是 INT8 W8A8，即权重和激活都量化。它同样使用第 2.2.1 节的等价变换，但主要目的是缓解激活异常值，让激活也更容易量化。

#### 2.3.1 激活异常值为什么难处理

假设某个 token 的激活包含：

```text
[0.5, -0.8, 100, 0.3, ...]

假设这些值共用一个对称 INT8 量化步长：
Δ = max(abs(x)) / 127 ≈ 100 / 127 ≈ 0.787

0.3 / 0.787 ≈ 0.381 → 舍入为 0
```

少数大值把步长撑大，普通小值只能被粗糙地表示。即使使用 per-token 激活量化，同一个 token 内不同通道仍可能出现这个问题。

SmoothQuant 通过校准识别幅度大的输入通道，把这些通道的激活缩小，并相应放大权重：

```text
例如选择某个通道 s[k] = 10：

该通道激活 100 → 10
对应权重       → 乘以 10

未量化的乘积不变；激活更容易量化，但权重可能更难量化。
```

它利用权重通常比激活更容易量化的特点，在两侧之间重新分配量化难度。不是删除异常值，也不是直接把激活截断到 10。

#### 2.3.2 缩放系数如何选择

沿用 X[M,K]、W[K,N]：

```text
a[k] = max_t abs(X_calibration[t,k])
       校准数据中，第 k 个输入通道的最大绝对激活值

b[k] = max_n abs(W[k,n])
       该输入通道对应权重的最大绝对值

s[k] = a[k]^α / b[k]^(1-α)

X_new[:,k] = X[:,k] / s[k]
W_new[k,:] = W[k,:] * s[k]
```

其中 α 控制迁移程度：

- α 越接近 1，越倾向于压平激活通道的幅度，把困难转移给权重。
- α 越接近 0，越倾向于让权重容易量化，把困难留给激活。
- α=0.5 时，在忽略零值和数值保护的理想情况下，同一输入通道两侧的最大绝对值都成为 sqrt(a[k]*b[k])。这是一种平衡，不保证所有模型最优。

实现需要对全零通道等情况设置数值保护，不能直接对零做除法。这里 a[k]、b[k] 是计算平滑系数的统计量，并不等于最终 INT8 激活和权重各自的量化步长。

矩阵形式可写成：

```text
D：由 s[k] 组成的可逆对角矩阵

XW = (X × D^(-1)) × (D × W)
```

#### 2.3.3 推理时是否要额外发射缩放 kernel

缩放系数通过离线校准确定，权重可以预先变换。对适合的网络位置，输入除以 s 的操作可以吸收到前面的 LayerNorm/RMSNorm 参数或其他相邻算子中，不一定需要额外发射一个逐元素除法 kernel。

这要结合计算图处理。例如同一份 RMSNorm 输出送往 Q/K/V 三个投影时，修改这份公共输入，需要配套调整所有相关分支；不能只改其中一个投影就认为整张图仍然等价。

“平滑系数离线确定”也不代表所有激活量化步长一定静态：后续激活量化仍可以采用运行时统计或校准得到的参数，取决于具体方案。

资料：[SmoothQuant 原论文](https://arxiv.org/html/2211.10438v7)、[官方平滑实现](https://github.com/mit-han-lab/smoothquant/blob/main/smoothquant/smooth.py)。

### 2.4 一张表记住区别

| 方法 | 优先记住的目标和手段 |
| --- | --- |
| GPTQ | 基于校准输入和近似二阶信息，补偿权重量化造成的层输出误差 |
| AWQ | 利用激活分布识别重要权重通道，通过缩放等降低 weight-only 量化误差 |
| SmoothQuant | 平滑激活离群值，把部分量化难度转移给权重，便于 W8A8 |

算法负责如何得到精度合适的量化模型，kernel 负责如何高效执行该格式。两者有关联，但不是同一项工作。

进一步对比 AWQ 与 SmoothQuant：

| 对比项 | AWQ | SmoothQuant |
| --- | --- | --- |
| 典型配置 | W4A16，低比特权重、浮点激活 | INT8 W8A8，权重和激活都量化 |
| 主要困难 | 部分权重量化误差被较大的输入激活放大 | 激活异常值撑大量化范围，影响其他激活的精度 |
| 激活统计的作用 | 识别重要权重通道，指导缩放搜索 | 衡量激活通道幅度，与权重统计共同确定平滑系数 |
| 共同变换 | 输入通道除以 s，对应权重乘以 s | 输入通道除以 s，对应权重乘以 s |
| 优化重点 | 降低低比特权重量化带来的输出误差 | 平衡两侧量化难度，使激活也适合 INT8 |
| 是否重新训练 | PTQ，不需要重新训练整个模型 | PTQ，不需要重新训练整个模型 |

典型执行路径也不同：

```text
AWQ W4A16：
INT4 packed 权重
    → 解包、反量化（可以融合在 GEMM 内）
    → 与 FP16/BF16 激活做浮点矩阵计算

SmoothQuant INT8 W8A8：
平滑后的激活 → 量化为 INT8
平滑后的权重 → 离线量化为 INT8
    → INT8 × INT8，通常 INT32 累加
    → 根据量化 scale 恢复尺度，完成后处理和类型转换
```

这些是典型实现，不是方法名称对所有硬件 kernel 的强制规定。尤其不要把 AWQ 的 W4A16 自动理解成 Tensor Core 原生执行 INT4×FP16；实际指令和解包路径需要查看实现。

面试口述：

> AWQ 和 SmoothQuant 都可以通过输入通道上的等价缩放改变数值分布。AWQ 根据激活统计保护重要权重，重点是降低低比特权重量化的输出误差，典型配置是 W4A16。SmoothQuant 则把激活异常值带来的部分量化难度转移给权重，重点是让权重和激活都能较准确地量化到 INT8，实现 W8A8。两者变换形式相似，但优化目标、缩放选择和推理计算路径不同。

## 3. 量化 GEMM 算子：70 分钟

### 3.1 先画清两条 W4A16 路径

```text
路径 A：显式重建
INT4 packed 权重
    → 解包、反量化
    → 完整 FP16 权重写入显存
    → FP16 GEMM 再读取权重
    → 输出

路径 B：融合执行
加载一小块 INT4 packed 权重
    → kernel 内解包、反量化
    → 与激活做乘加
    → 输出
```

融合路径可以避免完整 FP16 权重中间结果的显存写回与再次读取。但解包、数据重排、寄存器压力或指令利用不佳，也可能抵消这些优势。具体使用 CUDA core 还是 Tensor Core，要看实现和硬件，不能仅由 W4A16 推断。

### 3.2 INT4 怎么存和解包

```text
1 字节 = 8 bit，可存 2 个 4-bit 值
1 个 32-bit 字，可存 8 个 4-bit 值

简化示例：从 32-bit packed 中取第 i 个 4-bit 片段
q_unsigned = (packed >> (4 × i)) & 0xF
```

这只是解释基本位操作。真实格式还可能有重排、交错、置换、特殊 zero 编码以及有符号表示，不能直接假设第 i 个片段就是矩阵中顺序第 i 个元素。

例如无符号 INT4 使用 [0,15] 再减 zero point；二补码有符号 INT4 使用 [-8,7]，解包时需要正确解释符号。两者不能混用。

### 3.3 分组反量化与矩阵乘

沿 K 维分组时：

```text
g = k // group_size
W_hat[k,n] = scale[g,n] × (q[k,n] - zero[g,n])

Y[m,n] = Σ_k X[m,k] × W_hat[k,n]
```

重点：scale 如果随 K 的 group 改变，就不能对整个 K 求和后只乘一个统一 scale。必须在正确的分组层级应用尺度。

### 3.4 GEMM kernel 应能讲到的实现点

| 实现点 | 应能解释什么 |
| --- | --- |
| 输出分块 | 一个线程块/程序实例负责怎样的 M×N 输出 tile |
| K 维循环 | 如何逐块加载并累加，量化 group 与 K tile 是否对齐 |
| 数据复用 | 激活、权重如何被多个输出复用 |
| 合并访存 | 相邻线程访问是否有利于连续、对齐读取 packed 权重和 scale |
| 寄存器/shared memory | 减少重复访存的同时，是否引入寄存器压力、降低占用率 |
| 累加类型 | 存储、乘法、累加、输出类型分别是什么 |
| epilogue | 最后如何加 bias、转换类型或融合后处理 |
| 边界与 mask | M/N/K 非整除、尾 group、不连续输入和越界保护 |

### 3.5 与 W8A8 整数计算对照

常见执行方式：

```text
激活量化为 INT8 + INT8 权重
    → 整数点积，通常 INT32 累加
    → 按激活/权重 scale 恢复尺度
    → bias、后处理和输出转换
```

若 zero point 非零，乘积中会出现修正项：

```text
(qx - zx) × (qw - zw)
= qx × qw - zx × qw - zw × qx + zx × zw
```

沿 K 求和时，要正确处理相应的求和修正。对称量化可以简化其中的 zero-point 处理。scale 能否在最后统一应用，仍取决于其共享维度。

### 3.6 建议阅读材料与小练习

阅读：[Marlin：FP16×INT4 推理 kernel 的设计说明](https://github.com/IST-DASLab/marlin)。先看 README 中的数据布局、访存与计算重叠等设计，不必逐行读完源码。

如果有余力，用纸笔或简单 CPU 参考代码走通：

```text
小矩阵 W
    → 按 group 求量化参数
    → 得到 q
    → pack 两个 4-bit 值到一个字节
    → unpack
    → W_hat
    → X × W_hat
```

练习目标是理解表示和索引，不是临时宣称实现了高性能 GPU kernel。

## 4. 性能与正确性验证：35 分钟

### 4.1 为什么量化不一定更快

- 小 M 的 decode 常对权重读取带宽敏感，压缩权重可能减少显存读取。
- M 增大后，权重复用增强，计算效率的重要性增加。
- 解包、反量化、数据重排、scale 读取和额外 kernel 发射都有成本。
- 临时 FP16 权重缓冲会增加显存占用与读写。
- 算子是否匹配目标硬件、库是否选择适合小 M 的路径，会显著影响性能。
- 长上下文 decode 还可能受 KV 读取、attention 等限制；不能把整个 decode 都归为权重带宽问题。

具体选路阈值应扫描 M/N/K 实测。prefill 通常 M 大、单请求 decode 通常 M=1，但批量 decode、短 prefill、投机验证会改变这个关系。

### 4.2 两种误差验证必须分开

| 验证 | 比较对象 | 检查什么 |
| --- | --- | --- |
| kernel 正确性 | 自定义 kernel vs 同一份量化权重的参考反量化＋矩阵乘 | 解包、索引、scale、边界和累加实现 |
| 量化质量 | 量化模型 vs 原始高精度模型 | 量化本身造成的模型质量损失 |

不能只拿量化 kernel 与原 FP16 权重的 GEMM 比较，否则量化误差和实现错误会混在一起。

算子测试要覆盖：

- 常见形状与 M=1、小 M、大 M。
- M/N/K 非 tile 整数倍、group 边界和尾部。
- 全零、极值、不同 scale/zero、格式约定支持的输入。
- 最大绝对误差、相对误差或整体误差指标；接近零的参考值不适合只看相对误差。

模型层面再看困惑度、目标任务质量等，不能用随机 prompt“有输出”替代量化质量验证。

### 4.3 性能怎么测

1. 固定设备、数据类型、布局、形状和量化参数，保证对照等价。
2. 做适当预热，明确是否包含量化、repack、分配和数据搬运时间。
3. 用设备事件测 GPU 阶段；端到端另测主机调度和整体延迟，避免混淆口径。
4. 不要给每个算子插同步后，直接把结果当成原生产执行路径的自然耗时。
5. 扫描 M/N/K、group size 等参数；不要从 M=1 外推全部小 M。
6. 查看实际执行的 kernel，torch.mm 与直接调用 BLAS 未必走同一实现。
7. 回到模型验证 TTFT、TPOT、吞吐和稳定性，记录输入输出长度及并发条件。

### 5.2 项目里两步优化的逻辑

```text
原自定义量化路径
    ↓ 放宽 M 分支条件，保留其他约束
reconstruct + muBLAS
    ↓ 小 M 下进一步比较相同形状的矩阵乘实现
接入 ATen 矩阵乘路径
```

报告记录吞吐：9.07 → 15.42 → 21.21 tok/s。使用这些数字时应明确是报告中的对应测试条件，不能和其他模型、不同口径的 A30 数据直接拼接比较。

可支持的结论：当时相应形状和环境下，原小 M 量化路径低于替代实现的效率；第二步又改善了库矩阵乘选路。

尚不能直接支持的结论：

- 已证明某一条 NVIDIA intrinsic 是全部性能差距的根因。
- 单凭 MLP 慢就证明量化 kernel 有问题。
- 只测 M=1 就能证明所有低 M 都应使用同一路径。
- 吞吐改善就证明长生成 Segfault/卡死已修复。
- 从零开发了整个 GPTQ kernel 或 GPTQ 量化算法。
